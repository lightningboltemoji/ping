# Builds keep their Accessibility grant

> Change `1794796156` — 2026-11-15

## Goal

Every build was signed ad hoc, and TCC pins an ad-hoc grant to the build's cdhash. Every `make install`
and every update therefore came back with no Accessibility grant, and Ping without the grant reads an
empty Dock without saying so. Releases were in the same position: the workflow would sign with a
Developer ID once one existed, and none did. This brings over the setup emira already uses.

## Implementation

**A self-signed certificate, CN `Ping`, signs both local builds and CI builds.** Its designated
requirement is `identifier "zip.tanner.ping" and certificate leaf = H"c95eb20d…"`. A rebuild changes
neither part, and a CI build signed with the same key is the same app to TCC as a local build. The cert
is valid for 20 years and lives in the login keychain. Its p12 is backed up outside the repo. A new key
means every user grants once more.

**The Makefile looks the certificate up by name and signs with its hash,** since codesign matches an
identity name as a substring. It falls back to ad hoc when the keychain doesn't have it: a fresh
machine, or CI's pull-request job. `CODESIGN_IDENTITY` given explicitly, which is what the release
workflow does, wins and adds a secure timestamp. A local build skips the timestamp so it doesn't need
the network. Any real identity turns on the hardened runtime. Ping uses no JIT, no plugins and no
entitlements, so the hardened runtime should change nothing, and the functional check below found no
difference.

**The release workflow needs no new logic.** Its import step already took any p12 from the
`production` secrets. Only the step name and the Gatekeeper warning said "Developer ID" or "ad-hoc".
The notarize step stays, gated on `APPLE_ID`. A self-signed cert can't be notarized, so it is skipped.

Rejected: a Developer ID ($99/yr, and it would also notarize, removing Open Anyway on downloads), and
the free Apple Development cert, whose subject carries the account owner's name and email and which
isn't meant for distribution.

## Observations

Verified locally, on macOS 27.2. After `tccutil reset` the grant was stored with a 72-byte
certificate requirement, not the old 40-byte cdhash one. A `BUILD=9999` rebuild with a new cdhash was
installed over it and relaunched. The row's `last_modified` didn't change, `codesign -R` against the
stored requirement passed, and `ping-dot-app watch` still listed the Dock's apps. tccd logged no check
for the relaunched pid, so there's no tccd verdict to quote.

- **Everyone on an ad-hoc build grants once more** on their first signed build, because the identity
  type changed. After that, updates keep the grant.
- **Gatekeeper still rejects the download** (`spctl --assess` says rejected). A browser download needs
  Open Anyway once. Only a Developer ID with notarization removes that.
- Ping reads nothing from the Keychain, so the self-signed cert's one Keychain prompt per build doesn't
  apply here.
- The CI half isn't exercised until the `production` environment holds `MACOS_CERTIFICATE`,
  `MACOS_CERTIFICATE_PASSWORD` and `MACOS_SIGNING_IDENTITY`. After that, a `tip` build should carry the
  same designated requirement as a local build.
