# `watch` publishes the Dock

> Change `1790302385` — 2026-09-24

## Goal

Something other than Ping should be able to show what Ping reads. The motivating case is bario, a
menu bar replacement, putting an app's badge in the bar: the app's icon beside its count or its word,
restyled by state — past a threshold, a word rather than a number, acknowledged, snoozed. A bar is only
one consumer, and none of them should need a second Dock reader, a second Accessibility grant or a
second poll to get facts Ping already has.

Ping also flattened any badge that was not digits to `""`. A test app that set `badgeLabel` to `"!"`
and to `"New"` showed both verbatim in `AXStatusLabel`, so "the badge is a word" was a state the Dock
reports and Ping discarded.

## Implementation

**A stream on Ping's own socket, not a reader in the CLI.** `ping-dot-app watch` could have read the
Dock itself, but the grant belongs to whoever runs it: a bar that launched it would need
Accessibility, and the CLI would have to link `PingCore` and AppKit. Asking the running app keeps the
CLI on the far side of the fence and makes Ping the one reader on the machine. The cost is that
`watch` needs Ping running, which is also what makes acknowledgement and snooze publishable at all,
since they exist only in the app. emira's `watch` is the precedent. Rejected for the same reasons it
gave: calling a consumer couples Ping to it, a distributed notification gives a late joiner no
snapshot, and a broker is more machinery than either side. A reader inside bario was the other
candidate. It would have been less code, and a second reader with a grant of its own for facts one
reader already has.

**`PingWatch`**, a fourth library with no dependencies, holds both ends of the socket, because the CLI
has to dial it and the app has to serve it and neither may pull the other in. The fence test pins it
to Foundation and Darwin. `DockStatus`, what a line says, lives in `PingCore` beside the snapshot it is
built from.

**Connecting is watching.** There is no request line: a connection is sent the latest reading and
every one after, and nothing a watcher writes is read. That keeps the socket publish-only, which is what
`PRINCIPLES.md §3`'s "Ping owns no input" still asks for. A verb added later can be a first line a
watcher never sends.

**`DockStatus` follows emira's two rules for a reader that merges lines.** Every key is always present,
so a badge that went away is said to be gone. `apps` is an array rather than an object keyed by
title, so a merge replaces it whole. Keyed by title, an app that left the Dock would have stayed in the
reader's copy forever, since nothing would ever send its key again. It lists every Dock app, badged or
not, because a consumer drawing an app's icon needs its path before the app has anything to say.

**Latest wins, per watcher.** A line already begun is finished, and one still waiting is replaced by
a newer one. A write source is resumed only while a write would block. Tested by publishing 400 lines
of 8 KB to a watcher that is not reading: it receives fewer than 400, all whole, in order, ending
with the newest.

**A word is kept as spelled and drawn as a dot.** `DockItem.badge()` keeps whatever string the Dock
gives. `Badge.kind` is still `count` only for digits, so every effect draws exactly what it drew
before: the notch and shelf already key on `kind`, and acknowledgement already treated any non-number
as a dot. Only `watch` sees the spelling.

**Verified by running it.** The dev binary was started from a terminal, which holds the grant, with
`PING_CONFIG` pointed at a missing file so nothing was drawn. `BADGES` drove Safari from 3 to 12 and
gave Finder a bare dot, and a test app put a real `"New"` badge on its own Dock tile. `watch` printed
the current reading on connect and one line per change. The word arrived as `"New"` with a null
`count`, about half a second after the tile appeared, and each line appeared once. With Ping stopped,
`watch` exited 69. A socket file left by a `SIGTERM` was replaced by the next start. A 40-second soak
had one long-lived watcher, four badge cycles, and twelve short-lived watchers connecting and leaving
in between. It received all seventeen lines. bario ran against it with a WASM item per app. Getting
that to work surfaced a bug in bario's `exec`, fixed there: every `FileHandle.bytes` in a process
reads on one serial queue, so a quiet `emira watch` held up Ping's lines.

## Observations

- Once, before the final build, a watcher driven by a test script stopped receiving lines that a new
  connection was then sent. It did not recur in any later run, including the soak, or with tracing on
  every publish and write. The likeliest cause is the test script killing its reader mid-run. If it
  comes back, a watcher's trace of `send` and `write` is the first thing to look at.
- A half-close reads as leaving, so `nc -U` with stdin at end of file is dropped. The CLI never
  half-closes. emira keeps a half-closed watcher with a zero-byte write test, and so could this.
- `SIGTERM` skips `applicationWillTerminate`, so the socket file stays until the next start replaces
  it. `watch` meanwhile reads it as nothing listening, which is the truth.
- There is no `ping-dot-app ack`. A bar that shows a badge will want clicking it to acknowledge,
  but that makes the socket take commands, which is a principles change rather than a verb.
- `snoozed` is a boolean. A consumer that wants to say how long is left would need `snoozed-until`.
